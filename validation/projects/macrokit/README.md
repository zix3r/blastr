# macrokit

A small configuration layer for a thermal process controller. It knows about physical
dimensions and units, parses operator text into typed settings, keeps an engine of
effective values with provenance, validates cross-field rules and exposes a tiny command
registry. It pretends to be the config crate of a pump station: everything an operator
types (`set fluid.flow.nominal 0.0025 m3/s`) goes through a unit registry, a schema and a
validator before the loop is allowed to run.

## Crates

| Crate | Path | What it is |
| --- | --- | --- |
| `macrokit-derive` | `crates/macrokit-derive` | `proc_macro` crate written by hand (no `syn`/`quote`): `#[derive(Describe)]` and the `#[command]` attribute macro, including the token parsers for structs, generics, field attributes and command options |
| `macrokit` | `crates/macrokit` | The library: dimensions, units, quantities, typed setting values/kinds/specs, the schema, the engine with provenance and change log, the rule set and the command registry. `build.rs` generates three lookup tables into `OUT_DIR` from `data/*.txt` |
| `macrokit-station` | `crates/macrokit-station` | Application crate on top of `macrokit`: a thermal profile read from the engine, derived duty/pump-power estimates and four extra commands registered with `#[command]` + `command_table!` |

Features: `default = ["metric"]` ships the SI prefix helpers (`crates/macrokit/src/metric.rs`);
the optional `imperial` feature adds `crates/macrokit/src/imperial.rs` (Fahrenheit, psi, US
gallon) and flips `quantity::PREFERRED_TEMPERATURE`, so that file is inactive by default.

Build script output (`$OUT_DIR/tables_gen.rs`, included by `src/generated.rs`): the unit
table, the prefix table and the baseline schema seed. It is sorted, byte-for-byte
deterministic, and writes nothing outside `OUT_DIR`.

## Tests

* unit tests: `#[cfg(test)] mod tests` in every module that owns logic,
* integration tests: `crates/macrokit/tests/{schema_pipeline,commands,derive}.rs` and
  `crates/macrokit-station/tests/{session,macros_across_crates}.rs`,
* no doctests, no filesystem access, no randomness; the whole suite runs in well under a
  second.

`cargo build --all-targets`, `cargo test --workspace`, `cargo clippy --all-targets --
-D warnings` and `cargo fmt --all -- --check` are clean, with and without
`--features macrokit/imperial`.
